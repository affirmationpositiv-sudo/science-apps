🏗️ Architektur

Die Renaissance App basiert auf einer Client-zentrierten Architektur mit optionalem Cloud-Backend. Der Fokus liegt auf Offline-First, datenschonendem Design und nahtloser Integration externer KI-Dienste.

Layer-Architektur (Übersicht)

🖥️Presentation Layer
HTML + CSS + Vanilla JS
Responsive, PWA-ready
🧩Application Layer
State Management
Routing, Business Logic
🔌Integration Layer
OpenRouter API
Firebase/Supabase Auth
🗄️Data Layer
localStorage (offline)
Cloud-DB (optional)
⬇ request / ⬆ response

🔑 Schlüsselentscheidungen

  • Offline-First: Alle Kernfunktionen funktionieren ohne Internet. Daten werden lokal gespeichert (IndexedDB / localStorage) und bei Verbindung asynchron mit der Cloud synchronisiert.
  • Kein eigenes Backend nötig: Authentifizierung via Firebase Auth oder Supabase. KI-Assistent via OpenRouter API (direkt aus dem Frontend mit API-Key).
  • PWA: Service Worker + Manifest → installierbar auf dem Homescreen, Push-Benachrichtigungen.
  • Ein-Page-Architektur (SPA): Hash-basiertes Routing, keine Server-Renderings notwendig.

🔄 UI-Flow

Der Benutzer durchläuft die App in einer natürlichen Progression: Onboarding → Tägliche Routine → Wachstum → Vertiefung.

→
⑤Live-CoachingPremium-Vertiefung

📱 Screen-by-Screen Navigation

  • Screen 1 – Login: Google / Apple / E-Mail. Nach erfolgreichem Login → Weiterleitung zu Screen 2 (Onboarding-Chat) bei erstmaligem Besuch, sonst zu Screen 3 (Dashboard).
  • Screen 2 – KI-Chat: Erster Chat = Onboarding. Der KI-Assistent lernt den User kennen, fragt nach Zielen und schlägt erste Skills vor. Danach als permanenter Coach verfügbar.
  • Screen 3 – Skill-Tree: Haupt-Dashboard. Zeigt alle 5 Skill-Bäume mit Fortschritt. Von hier aus Training starten, Details einsehen oder Quests anzeigen.
  • Screen 4 – Daily Quests: Tägliche Missionen mit XP-Belohnungen. Main Quest, 3 Daily Quests + Weekly Challenge. Abschluss aktualisiert Skill-XP.
  • Screen 5 – Live-Coaching: Buchungs- und Verwaltungsseite für 1:1-Sessions mit dem persönlichen Coach. Nur sichtbar für User mit Coaching-Paket.

Routing-Entwurf

#/login        → Screen 1 (Login)
#/chat         → Screen 2 (KI-Assistent)
#/skills       → Screen 3 (Skill-Tree Dashboard)
#/quests       → Screen 4 (Tägliche Quests)
#/coaching     → Screen 5 (Live-Coaching)
#/profile      → User-Profil & Einstellungen
#/settings     → App-Einstellungen (Dark Mode, Sprache, etc.)

🗺️ Entwicklungs-Roadmap

Phase 1 – Foundation (Woche 1)

🎯 Ziel: Funktionsfähige Web-App

  • Tag 1: Projekt-Setup, HTML-Struktur, CSS-Design-System, PWA-Manifest + Service Worker
  • Tag 2: Login-Screen (Google OAuth via Firebase/Supabase), Routing (#/login)
  • Tag 3: KI-Assistent Chat – OpenRouter API-Integration, Nachrichten-Historie (localStorage)
  • Tag 4: Skill-Tree Dashboard – Datenmodell, 5 Skill-Karten, XP-System, Level-Up-Logik
  • Tag 5: Daily Quests – Main Quest + 3 Dailies + Weekly Challenge, Quest-Logik + XP-Vergabe
  • Tag 6: Live-Coaching Screen – Buchung, Pakete, Kalender-Integration (simuliert)
  • Tag 7: Testing, Bugfixes, Deployment (Netlify / Vercel), Dokumentation
Phase 2 – Mobile & Backend (Woche 2–3)

🎯 Ziel: Native-App-Feeling + Cloud-Backend

  • React Native / Flutter Port (Mobile Apps für iOS & Android)
  • Cloud-Backend mit Supabase (Datenbank + Auth + Realtime)
  • Sync-Engine: Offline → Cloud (Konfliktlösung via Last-Write-Wins)
  • Push-Benachrichtigungen (Erinnerungen, Streak-Alarme)
  • Ranking & Leaderboards (Community-Feature)
  • Zahlungsintegration (Stripe für Abos + Coaching)
Phase 3 – Scale & AI (Woche 4+)

🎯 Ziel: Intelligentes, personalisiertes System

  • KI-gestützte Skill-Empfehlungen (basierend auf User-Verhalten)
  • Adaptive Quests (Schwierigkeit passt sich an Fortschritt an)
  • Sprach-Assistent (Speech-to-Text für Coaching-Notes)
  • Dashboard mit erweiterten Analytics (Fortschritt-Charts, Insights)
  • Community-Features: Gruppen-Challenges, Skill-Sharing, Mentoring
  • Internationalisierung (Englisch, Spanisch, Türkisch)

Risiken & Mitigation

  • OpenRouter API-Kosten: Rate-Limiting + Caching häufiger Antworten. Fallback: lokale Simple-Response-Engine bei API-Ausfall.
  • Datenschutz: Alle sensiblen Daten lokal. Cloud nur mit explizitem User-Consent. DSGVO-konform.
  • Offline vs. Online Sync: Konflikte bei gleichzeitiger Bearbeitung. Strategie: Last-Write-Wins + Konflikt-Log für Admin-Review.
  • PWA-Einschränkungen: Kein Zugriff auf native APIs (HealthKit, Sensoren). Phase 2 (native Apps) löst dies.
